# Usage Guide

This guide covers how to configure and execute the pipeline for different analysis scenarios.

## 1. Prepare Your Data
The pipeline expects a `config/samples.yaml` file (or equivalent) to define your sample IDs and data paths. 

## 2. Configure the Pipeline
All analysis logic is controlled in `config/pipeline.yaml`. 

### Scenario A: 2nd Gen Metagenomics (Short-reads)
- Set `binning: enable: True`
- Set `binning: mode: "standard"`
- Set `annotation: data_type: "short"`

### Scenario B: 3rd Gen Genome Analysis (Long-reads)
- Set `assembly: enable: True` (if starting from raw reads)
- Set `annotation: data_type: "long"` (enables ISEScan and Bakta --complete)
- Set `plasmid_analysis: enable: True` (to identify circular plasmids)

### Scenario C: Hybrid Metagenomics (LR Assembly + SR Coverage)
- Set `binning: enable: True`
- Set `binning: mode: "hybrid"`

> [!IMPORTANT]
> **Linking Binning to Annotation**: 
> If you want to annotate the Bins generated by the `binning` module, set `annotation: input_dir: results/binning/all_bins_combined` and `annotation: data_type: "short"` in your `pipeline.yaml`.

## 3. Execution

### Dry Run (Always do this first!)
```bash
snakemake -n
```

### Run on SLURM Cluster
```bash
snakemake --profile profiles/slurm
```

### Using a Custom Config Directory
If you have multiple projects or configuration sets, you can specify which config directory to use:
```bash
snakemake --config conf=config_pi
```
This will load `config_pi/pipeline.yaml` and automatically redirect all module paths (e.g., `config/preprocess.yaml`) to the corresponding files in `config_pi/`.

## 4. Output Structure
Results are organized hierarchically:
- `results/preprocess/`: Clean reads and QC reports.
- `results/assembly/`: Contigs and assembly metrics.
- `results/binning/`: Dereplicated MAGs (for SR/Hybrid).
- `results/annotation/`: GFF, FAA, TSV, and functional reports.
- `results/plasmid_analysis/`: Comprehensive plasmid reports.
